### Структура базы данных

В проекте реализована схема музыкального магазина, состоящая из 6 основных таблиц:

* `categories` — категории товаров
* `suppliers` — поставщики
* `customers` — клиенты
* `products` — справочник товаров с поддержкой версионирования (SCD2)
* `orders` — заказы
* `order_items` — позиции заказов (строки чека)

### Валидация данных

Для поддержания качества данных реализован триггер `trg_before_insert_customer` на таблице клиентов. Он проверяет:

* Корректность email-адреса (обязательное наличие символов `@` и `.`).
* Корректность номера телефона (защита от попадания буквенных символов)

### Загрузка данных и SCD2

Импорт базовых данных из CSV-файлов выполнялся средствами DBeaver. Для таблицы `products` реализован механизм отслеживания исторических изменений (SCD2):

* Данные загружаются через промежуточную таблицу `stg_products`.
* Процедура `load_products_scd2()` автоматически обрабатывает изменения:
* При вызове процедура закрывает старые версии товаров, если изменились ключевые атрибуты (цена или название)
* Добавляет новые товары и актуальные версии измененных товаров
* Очищает промежуточную таблицу после успешной транзакции



### Индексы

Для ускорения работы БД и аналитических запросов (в `order_items` загружено ~12к строк) созданы индексы:

* Частичный (filtered) индекс по таблице `products` для быстрого поиска только актуальных версий товаров.
* Индексы по внешним ключам для таблиц `order_items` и `orders` для оптимизации `JOIN` соединений

### Аналитический запрос

SQL-запрос с использованием CTE и оконных функций для анализа структуры выручки магазина. Логика запроса:

* Ранжирует товарные категории по объему принесенной выручки (от большего к меньшему)
* Детализирует продажи внутри каждой категории, вычисляя процентную долю каждого конкретного товара в общей выручке этой категории
* Строку `EXPLAIN ANALYZE` раскоментить/закоментить в зависимости от того, нужно ли получить план запроса или результат запроса
